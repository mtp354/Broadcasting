**Confirmed findings, ordered by practical priority**

1. **The convergence figure repeats one seed while claiming independent repeats.**
   `scripts/generate_figures.py:50` fixes `conv_config.seed=0`, while line 61
   varies only `SamplingBackend(seed=seed)`. `broadcasting/backend.py:117`
   gives the config seed precedence. `run_broadcast.ipynb:305` and `:316`
   repeat the same mistake. Three supposedly different seeds produced
   bit-identical results in a local reproduction; leaving the config seed unset
   produced different results. The fitted single-seed curve may still resemble
   the expected scaling, but the claimed independent repetitions and across-seed
   uncertainty are invalid. Set the effective seed explicitly per repetition,
   save the convergence measurements, then regenerate Fig. 1 and its description.

2. **Result saving can still overwrite existing data, and sampling metadata can
   describe a different execution.** In `broadcasting/results.py:34`, the SLURM
   suffix is constant within one job/task. Two saves within the same second in
   that task resolve to the same path and `open(..., "w")` at line 174 overwrites
   the first file; this was reproduced in a temporary directory. Explicit paths
   also overwrite. The README's unconditional never-overwrites claim is false.
   Use per-save uniqueness and exclusive creation, preferably with atomic
   publication of complete records. Separately, line 112 prefers
   `config.n_samples` over the executed count and line 158 saves only the config
   seed. A real seven-trajectory run using backend seed 314 serialized as **200
   trajectories, seed null** with a default config. Record effective execution
   settings and preserve `linear_feedforward`, outcome selection, and circuit
   identity for reproducibility.

3. **Sender-outcome diagnostics read the wrong classical register.**
   `broadcasting/circuit.py:116` names it `m`; both extraction paths inspect
   `c_senders` at `broadcasting/backend.py:386` and `:512`. Actual local sampler
   output contains `m` and `fid`, and both backend paths consequently return
   null sender counts and invalid-outcome rates. Read the real register and add
   integration coverage using actual result-register names. Separate register
   histograms alone will not preserve sender/syndrome/receiver shot alignment;
   archive aligned outputs if conditional diagnostics are intended.

4. **The regenerated figures do not consistently match what the manuscript says.**
   Fig. 6's caption at `manuscript/apstemplate.tex:545` still says Kingston and
   10,000 shots, whereas its image includes Fez, Marrakesh, and Kingston.
   `scripts/generate_figures.py:294` prints cohorts but then plots every hardware
   run, dropping shot counts and optimization levels from point identity. The
   collection also includes historical and recent circuit variants. Printing
   cohorts is not sufficient to establish a controlled scaling experiment.
   Either select a defensible cohort or label the heterogeneous evidence fully.
   Fig. 2 embeds `qec513_delay_sweep_idle.png` at manuscript line 428, but the
   generator writes `qec fidelity.png` at script line 164, leaving the actual
   embedded figure untouched. Historical QEC records omit `use_qec`, so encoding
   labels need evidence-backed provenance rather than guesses. Fig. 4's caption
   and text at manuscript lines 522 and 533 promise an inset that the new image
   does not contain. Establish an explicit figure-to-source manifest, including
   run IDs, execution settings, units, and output filenames. Keep raw records
   unchanged. The crossover selector also takes the first matching runs and
   applies the bare run's p-grid to every curve without checking grid equality;
   current selected grids match, but this is fragile when records change.

5. **The HPC interface can change the requested experiment or mislabel a merge.**
   `broadcasting/backend.py:205` exports only minimum, maximum, and count, and
   `hpc/run_experiment.py:100` reconstructs a linspace. Requested points
   `[0, 0.1, 1]` become `[0, 0.5, 1]`. Preserve the explicit list or reject
   unsupported grids. `scripts/merge_hpc_runs.py:37` omits theta samples and
   experiment identity from its fingerprint. Two different-theta inputs were
   accepted and merged under the first input's theta metadata. Include the full
   experiment-defining settings and validate completeness against the intended
   sweep. The README's broad `results/run_*.json` example also includes complete
   sweeps that the merger rejects; narrow the documented inputs. Finally,
   `backend.py:252` stores the displayed command using a plain space join:
   multi-sender theta/outcome arguments do not survive shell copy/paste. Store
   argv and use shell-aware formatting for the displayed command. The shared
   scratch lock prevents simultaneous syncs within an array, but does not isolate
   running submissions from later submissions replacing the same source tree.

6. **Both optional analysis paths in the main notebook need repair.**
   The convergence cell calls `np.trapz` at `run_broadcast.ipynb:318`, which is
   absent in the installed NumPy; the standalone generator already uses
   `np.trapezoid`. The periodicity cell calls `autocorrelation_from_run` without
   importing it, and its saved-run selector at line 395 looks for nested
   `protocol.N` although `load_run` exposes `N` at the top level. The selector
   found zero records despite 12 existing N=2 tau sweeps. Add local execution
   checks for the optional cells as well as unit tests for helpers.

7. **Timing conversions and backend compatibility remain incomplete.**
   Main hardware results now record backend `dt`, but notebooks and the figure
   script still use a fixed `4e-3` microseconds per dt. The QEC benchmark prints
   backend dt but does not persist it. Consume recorded dt and use explicit,
   justified historical overrides where necessary. Separately,
   `broadcasting/plotting.py:499` rescales autocorrelation lags but leaves PSD
   frequencies unchanged while labeling them in inverse microseconds. A synthetic
   period of 200 dt at 0.004 microseconds/dt was plotted at **0.005 instead of
   1.25 cycles/microsecond**. Rescale frequency and spectral-density units
   consistently. The notebook's direct frequency conversion is already correct.
   Finally, symbolic-delay transpilation at `backend.py:478` fails on the
   installed FakeBrisbane target with an instruction-duration error, although
   Kingston/Marrakesh/Fez work. Add target-aware validation/handling while retaining
   once-per-theta compilation where supported. These are offline compatibility
   observations, not claims about a newly submitted hardware job.

8. **The manuscript's new privacy statement is mathematically incorrect.**
   `manuscript/apstemplate.tex:129` and `:556` say the classical outcomes reveal
   the aggregate sender phase. From the manuscript's resource and Fourier
   equations, orthogonality of the Dicke terms gives
   `P(outcomes | phases) = (N+1)^(-M)`. Thus the classical correction transcript
   contains no phase information; the receivers' quantum states encode the
   aggregate phase. Correct the statement without inflating it into a broader
   security guarantee.

9. **Methods and scope still overclaim or contradict current evidence.**
   The abstract at `manuscript/apstemplate.tex:100` still promises conclusions
   about correlated physical errors that Results/Conclusion correctly qualify.
   Lines 414–418 suggest available scalar-only accumulation, omit the retained
   trajectory-list cost `O(n_samples * D)`, and claim timing/memory measurements
   not supplied by the pipeline. The stated sample-size range differs from the
   generator. The bare dense-matrix implementation also does not have the
   quadratic per-operation cost asserted at line 395. Describe the implementation
   actually retained, or measure the performance being claimed. Line 364 calls
   the production brute-force helper independent although it shares recovery
   helpers; cite the genuinely independent oracle in
   `tests/test_qec_recovery.py:224` instead. Clarify that integrated QEC broadcasting
   exists in library circuits and simulation, while reported hardware QEC data
   are a standalone encoded-memory benchmark. Update exhaustive-feedforward
   descriptions to match the current default bitwise circuit.

10. **Some public inputs fail late or are silently reinterpreted.**
    `HardwareBackend.run()` with default `tau=None` submits an unbound parameter;
    choose an explicit single-point default or reject it early. Duplicate tau
    values alias the same grid slot through `backend.py:492`, so validate delay
    lists before submission. `broadcasting/fidelity.py:54` silently removes the
    imaginary part of alpha instead of enforcing its documented real-input
    contract. An ideal target with `alpha=0.5+0.5j` then measures fidelity
    **0.806186 instead of 1**. Existing real-alpha results are unaffected; reject
    complex input consistently or implement its phase. The real-alpha regression
    coverage removed with the structured-circuit tests should be restored.
